# __name__ 与 import机制

每个python文件都有自己的__name__ 属性，
从python xxx.py的底层出发：

Python 解释器（C 语言编写）在运行一个 .py 文件时，不是像 shell 脚本那样顺序“执行”文本，而是将其编译成字节码（Code Object），然后在一个特定的字典（命名空间）中执行这些字节码。

__name__ 本质上就是这个命名空间（globals() 字典）里的一个键值对。这个键对应的值是什么，完全取决于解释器是怎么把你这个文件加载进内存的。
从 /home/ubuntu/projects/pythonStudy/python_base/__name__exmaple/main.py 可以看到，
使用python main时，main.py,和其引用的其他python文件都会被编译成字节码，sys.path里会存储引用的其他文件，

## 直接使用的 main（或者其他名字）
PyImport_AddModule 创建一个特殊的模块对象，这个对象在底层硬编码被命名为 "__main__"，在这个命名空间的字典里插入一个键值对：key = "__name__", value = "__main__"

## 其他被引用的
被引用的文件存储在sys.path中，走PyImport_Import机制，解释器不会使用 __main__ 对象，而是调用 PyModule_New 创建一个新的、独立的模块对象。
执行与缓存：在这个独立的命名空间里执行字节码之前，解释器同样会往这个命名空间的字典里插入键值对，但这次值是：key = "__name__", value = "a"（即模块名）。

存入缓存：执行完毕后，这个模块对象会被存入 sys.modules["a"]。



# import介绍

 执行 main.py 的字节码，碰到 import main_use 这行时，解释器会：

  1. 暂停 main.py 的执行；
  2. 递归地走一遍 import 流程去加载 main_use；
  3. 加载 main_use 时执行它的顶层代码，又碰到 import show —— 再次递归去加载 show；
  4. show 全部跑完后，控制权回到 main_use，再回到 main。

  所以 import 调用是栈式递归的，跟函数调用一样。

## 重复引用的show.py 为什么没有打印两次hello show1 and show？
import递归过程中，会先在sys.modules中找这些模块，没找到则搜索sys.path，找到则跳过。
show.py第一次import时sys.modules不存在，所以通过sys.path找，然后编译成字节码并 **执行** ，__name__ 然后存储到sys.modules，后续有缓存了就不再重复执行了

### sys.modules是什么
sys.modules是dict（字典，键值对）（dict[str, ModuleType]）。key 是 str，value 是 ModuleType
这个dict是__name__ : module对象

sys.modules['show'] = <module 'show'>   # 整个 module 对象
        ↑ key                  ↑ value

#### module对象是什么

Module 对象 = "一个 dict（命名空间）+ 一组元信息属性"

show.__dict__ = {
      'hello_show': <function hello_show at 0x...>,   ← 你 def 的
      '__name__':   'show',                            ← 元信息也在这个 dict 里
      '__file__':   '/.../show.py',
      ...
  }

关键性质：show.hello_show 这种点号访问，底层就是 show.__dict__['hello_show']。实验最后一行已经证明：

show.hello_show is show.__dict__['hello_show']   # True，是同一个对象

所以模块的"命名空间"不是一个抽象概念，它就是一个真实的 dict 对象，可以 print(show.__dict__) 直接看。


# 注意的点

## 命名空间隔离

每个模块的命名空间是隔离的 dict

 main_use 自己的命名空间里有：
    ['show', 'show_2', 'show_3', 'all_hello_show', ...]

main_use 的 __dict__ 里有 show，是因为它在顶层写了 import show。但这不会让 show 这个名字"漏"到 main.py 里。每个模块的命名空间是隔离的 dict。

  所以在 main.py 里：

  import main_use
  main_use.show          # ✓ 这样能访问到 show 模块（穿透 main_use 的命名空间）
  show                   # ✗ NameError，除非 main 自己也 import 过 show

## import的本质

一个 .py 文件 = 一个 module 对象，存放在 sys.modules 这个 dict 里，key 是它的"全限定名"（dotted name）。
但当import一个文件夹时：
key = 'show_folder.show_3'      ← 子模块，用点号串起来
注意 show_folder 这个目录本身也是一个 module（包模块，对应 __init__.py 或空包），所以"最小单元"严格说是 "模块"而不是"文件"——包也是模块，一个模块对应一份字节码，进 sys.modules 一次。

### import文件夹

python2 直接import一个文件夹时这个文件夹必须要有__init__.py,否则解释器的import模块无法判断为模块。

PEP 420 引入了命名空间包（namespace package）：一个没有 __init__.py 的目录也能被当作包导入：

| 类型 | 是否要 `__init__.py` | 加载器 | `__file__` | 包体代码 | 能否跨多目录拼接 |
|---|---|---|---|---|---|
| 常规包（regular package） | 要 | `SourceFileLoader` | 有（指向 `__init__.py`） | `__init__.py` 的内容就是包体，会被执行 | ❌ |
| 命名空间包（namespace package） | 不要 | `NamespaceLoader` | 无 | 无包体代码可执行 | ✅（可以把多个目录拼成同一个包） |

文件夹不一定要有 __init__.py。有它就是「常规包」，__init__.py 当包体执行；没有它就退化成「命名空间包」，仍能 import，但不会有包级代码跑、也拿不到 __file__
