# Tip 01：一个对象到底占多少内存 —— 从 PyObject 到 `__slots__`

> 参考资料性质：数据为本机实测（Python 3.13.9 / Windows 11 64 位 / 2026-09-04），
> 源码引用均指向本仓库 `cpython-3.13/`。所有脚本可复现（见文末）。
> 这属于「内存敏感场景下的工程决策」知识：海量小对象（10万+）时才值得用，
> 几十个对象用什么都无所谓。

---

## 1. 实测数据

### 1.1 基础体积

| 对象 | getsizeof | 说明 |
|---|---|---|
| `object()` | 16 B | 纯对象头 |
| `0` / `1`（int） | 28 B | 头 16 + `ob_size` 8 + 1 个 digit 4 |
| `2**62`（int） | 36 B | 62 位 → 3 个 30-bit digit：16+8+12 |
| 2 属性普通类实例 | 48 B | **浅大小，不含属性值的存储（见 §4）** |
| 2 属性 `__slots__` 实例 | 48 B | 头 16 + 2 个槽位指针 16 + 余量 |

### 1.2 十万实例的总内存（tracemalloc，含 int 属性值本身）

| 方案 | bytes/实例 | 相对 |
|---|---|---|
| 普通 class | 128.0 | 基准 |
| `__slots__` class | 87.9 | **−31%** |
| `@dataclass` | 128.0 | 同普通类 |
| `@dataclass(slots=True)` | 87.9 | **−31%** |

### 1.3 属性访问速度（100 万次 `obj.x`）

| 方案 | 耗时 |
|---|---|
| 普通（inline values → dict 路径） | 54.9 ms |
| `__slots__` | 44.7 ms（**−18%**） |

### 1.4 3.13 特有：碰一下 `__dict__` 的代价

| 场景 | bytes/实例 |
|---|---|
| 从不触碰 `__dict__` | 128.0 |
| 每个实例读一次 `obj.__dict__` | 191.9（**+64 B/实例**） |

`__dict__` 在 3.13 是**惰性实体化**的：不碰它，属性值以紧凑形式内联存储；
一碰（哪怕只读），CPython 就造出一个真 `PyDictObject`（getsizeof = 296 B）。

### 1.5 呼应 09 的 int/numpy 对比（100 万个整数）

| 方案 | bytes/元素 |
|---|---|
| `list` 装 Python int | 40.0（28 B 对象 + 8 B 指针 + 分配器对齐） |
| `np.arange(..., dtype=np.int64)` | 8.0（紧凑 C 数组，无对象头） |

5 倍差距的本质：Python int 是「对象头 + 30-bit digit 数组」的堆对象；
numpy 是「裸的连续 int64」。这和 `__slots__` 是同一个思想的两端——
**去掉逐对象的开销（per-object overhead）**。

## 2. 源码依据

### 2.1 对象头：16 字节起

`Include/object.h:163-186`（`struct _object`）：

```c
union {
   Py_ssize_t ob_refcnt;          // 64 位下 8 字节
   PY_UINT32_T ob_refcnt_split[2];
};
PyTypeObject *ob_type;            // 8 字节
```

8 + 8 = 16，这就是 `object()` 的全部。**任何** Python 对象都至少背着这 16 字节
（引用计数 + 类型指针）——这是「一切皆对象」的价格。

变长对象再加 `ob_size`（`Include/object.h:224-227`，`PyVarObject`），
int 就是：16 + 8 + digit 数组 → 小 int 恒 28 字节。

### 2.2 3.13 实例属性的存储：inline values

`Include/internal/pycore_object.h:784-790`：托管字典通过**负偏移**挂在对象尾部：

```c
#define MANAGED_DICT_OFFSET    (((Py_ssize_t)sizeof(PyObject *))*-3)
```

`Include/internal/pycore_object.h:810-817`：属性值可以**紧跟对象头之后内联存储**：

```c
static inline PyDictValues *
_PyObject_InlineValues(PyObject *obj)
{
    ...
    return (PyDictValues *)((char *)obj + sizeof(PyObject));
}
```

属性查找顺序见 `Objects/object.c:1571-1583`：先查 inline values，
不行再走 managed dict，最后才是传统 `tp_dictoffset` 字典。

### 2.3 `__dict__` 的惰性实体化

`Objects/object.c:1497`：访问 `__dict__` 时调用 `_PyObject_MaterializeManagedDict`
——这就是 §1.4 中 +64 B/实例 的来源。生产代码里**不要顺手打印/传递 `obj.__dict__`**
（调试器、`pprint(vars(obj))`、某些序列化库都会踩）。

### 2.4 `__slots__` 做了什么

`Objects/typeobject.c:4099`（`type_new_get_slots`）：类创建时把 `__slots__`
里的名字变成**描述符**（每个槽一个 member descriptor），并让实例失去
`__dict__`。属性访问从「哈希查 dict」变成「固定偏移取指针」——这就是 −18% 的来源。

### 2.5 `getsizeof` 的边界（重要！）

`Objects/typeobject.c:7199-7214`：`object.__sizeof__` 返回
`tp_basicsize + ob_size × tp_itemsize`——**只算固定部分**。

实测：0～10 个属性的普通类实例，getsizeof 全是 48 B。属性值存储在
inline values / 独立分配的 values 数组里，getsizeof 看不见。
所以**内存结论要用 `tracemalloc` 测，别信 getsizeof**（它连 `__dict__`、
引用的对象都不算，是「浅大小」）。

## 3. 工程用法

### 3.1 主流写法（3.10+）：dataclass 直接开 slots

```python
from dataclasses import dataclass

@dataclass(slots=True)
class Point:
    x: float
    y: float
```

一个参数同时拿到：内存 −31%、访问提速、属性防拼错（不能动态加）。
**新项目的数据载体类默认加 `slots=True` 是合理倾向**（3.10+ 才有此参数）。

### 3.2 何时值得用

- ✅ 量大的记录型对象：ORM 行缓存、爬虫结果、游戏实体、图/树节点
- ✅ 属性集合固定的任何「数据类」（配合 dataclass）
- ❌ 需要动态属性的：原型、ORM 的延迟加载代理、monkeypatch 测试
- ❌ 对象总数几千以内——省的那点内存不如代码灵活性值钱

### 3.3 三个已验证的坑（本机 3.13.9 实测）

1. **weakref 默认不可用**：`weakref.ref(obj)` → `TypeError`。
   需要弱引用（缓存、观察者模式）就加 `__weakref__` 进 slots。
2. **继承链一票否决**：父类没有 `__slots__` → 子类照样有 `__dict__`，
   slots 白写。整条继承链都要干净。
3. **pickle 没问题**（老资料说有坑，3.13 实测协议默认值下正常 round-trip）。

## 4. 思考题（留给自己的理解，别看答案先想）

1. `sys.getsizeof(2**62)` 是 36，那 `2**30` 和 `2**60` 应该是多少？
   先算（digit 是 30 bit 一个），再用 `sys.getsizeof` 验证。
2. 为什么 0～10 个属性的实例 getsizeof 都是 48？既然 basicsize 固定，
   第 5 个属性存到哪里去了？（提示：inline values 容量有限，
   超了以后去哪了——去 `Objects/object.c` 找 `_PyObject_StoreInstanceAttribute`）
3. `__slots__` 生效后属性访问变成「固定偏移」，这和你学过的哪个协议有关？
   （提示：typeobject.c 里 slots 的实现依赖哪种描述符？和 07 的数据描述符什么关系？）
4. numpy 比 list-of-int 省 5 倍，那什么场景下 Python int 反而是对的选择？
   （想想任意精度、溢出语义、和 C API 互操作的成本）
5. 既然 3.13 的 inline values 已经很省了，`__slots__` 还剩多少优势？
   什么时候 inline values 反而比 slots 更好？（提示：属性数不固定时）

## 附：复现脚本

```python
import sys, timeit, tracemalloc, weakref, pickle
from dataclasses import dataclass

class WithDict:
    def __init__(self, x, y): self.x, self.y = x, y

class WithSlots:
    __slots__ = ('x', 'y')
    def __init__(self, x, y): self.x, self.y = x, y

@dataclass
class DC:  x: int; y: int

@dataclass(slots=True)
class DCSlots:  x: int; y: int

def measure(make, n=100_000, touch=False):
    tracemalloc.start()
    objs = [make(i, i) for i in range(n)]
    if touch:
        for o in objs: o.__dict__
    cur, _ = tracemalloc.get_traced_memory()
    tracemalloc.stop()
    return cur / n

print('普通 class      :', measure(lambda x, y: WithDict(x, y)))
print('__slots__       :', measure(lambda x, y: WithSlots(x, y)))
print('dataclass       :', measure(lambda x, y: DC(x, y)))
print('dataclass slots :', measure(lambda x, y: DCSlots(x, y)))
print('碰 __dict__     :', measure(lambda x, y: WithDict(x, y), touch=True))

d, s = WithDict(1, 2), WithSlots(1, 2)
print('dict 访问 1M 次 :', timeit.timeit('d.x', globals={'d': d}, number=1_000_000))
print('slots 访问 1M 次:', timeit.timeit('s.x', globals={'s': s}, number=1_000_000))
```
